# Releasing 1.2.0

The maintenance-UI release, cut from `main` (v1.1.0 plus the maintenance work).
It follows the [1.1.0 checklist](1.1.0-checklist.md): the tag drives
[`release.yml`](../../.github/workflows/release.yml), and everything here is a
check before the tag or a verification after it.

## Before the tag

- [ ] **`main` is green** on the merge commit: `ci.yml` (Redocly lint, the
      generated reference, generated clients, Go tests, frontend check and
      build), `load-test.yml`, `proto.yml`, `security.yml`.
- [x] **API change classified.** `auto_status_pages` is a new optional,
      write-only request field on the maintenance-window writes: **additive**
      under [COMPATIBILITY.md](../api/COMPATIBILITY.md). Omitting it behaves as
      in 1.1.0.
- [x] **No migration.** `0009_artifact_mirror.sql` is still the latest.
- [x] **`CHANGELOG.md`** has a `## [1.2.0] — 2026-11-08` section and compare
      link. **Change the date if the tag goes out on another day.**
- [x] **No version in source.** `internal/version` still reads `dev`.

## The tag

```bash
git checkout main && git pull
git tag -a v1.2.0 -m "v1.2.0 — maintenance windows in the dashboard"
git push origin v1.2.0
```

Pushing the tag can't be undone. If something is wrong, fix forward with
`1.2.1`; never move or delete a pushed tag.

## After the tag

- [ ] **`release.yml` completes**: binaries, checksums, SBOM, multi-arch
      images on GHCR and Docker Hub.
- [ ] **The image reports its version:**
      `docker run --rm ghcr.io/webloomlabs/uptime-cairn:1.2.0 -version`
- [ ] **Upgrade a 1.1.0 install** and confirm nothing migrates, existing
      windows keep their status pages, and **Maintenance** appears in the
      navigation.
